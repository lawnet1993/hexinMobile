# 当前桌面进程接收移动端消息的数据层及时性复验（2026-09-06）

## 结论

本机当前运行的桌面进程使用 test01 有效测试会话，IM/OA Bootstrap 均为 200。test02 移动端通过真实 UI 向 test01 单聊发送一条新的 `AI-UAT-` 文本后，桌面消息缓存约 737 ms 检出新增消息，会话摘要投影约 2.623 s 更新到同一最新序号；服务端目标消息只有一条。

本轮证明当前桌面**入站落库和会话摘要数据投影**能够及时推进，不证明 Windows 可见聊天区或会话列表已经刷新。无影云电脑标签可以枚举，但连接标签在内核重置和一次恢复重试后仍连续超时，因此 UI 继续标记未验证。

## 环境与方法

- 移动端：`emulator-5554`，test02，当前 Profile APK。
- 桌面端：本机运行中的 `hexing-zhilian` 进程，test01 会话。
- 会话：test01 与 test02 的既有单聊。
- 发送：只通过移动端真实输入框和发送按钮，不调用消息发送 API。
- 桌面核对：SQLite 只读事务、现有授权测试会话的只读 GET 和脱敏聚合；不读取或输出 Token、设备 ID、消息正文、附件地址或会话 ID。
- 桌面 EXE 文件元数据仍为 1.0.87，历史真实窗口曾显示 v1.0.94；文件元数据与窗口版本来源不一致，本轮不据此声明当前 UI 版本。

## 证据边界

第一次观察器尝试在移动端真正点击之前已经结束，因此对应 42 秒空观察不能作为消息延迟或失败证据；最终结论只使用观察器先就绪、发送后再检出的第二轮精确联动。

当前仍需 Windows 可见窗口验证：

1. 新消息是否无需切换会话即可出现在聊天区；
2. 左侧摘要、时间和排序是否在投影更新后立即刷新；
3. 自己跨端发送的消息是否使用正确未读语义；
4. 图片、文件、视频和音频是否能从同一对象正常打开。
