# 870 · 当前 OA 动态表单配置文本运行态核对

时间：2026-09-09（Asia/Shanghai）  
设备：Android 16 模拟器 `emulator-5556`  
账号：Test Terminal 03

## 结论

当前测试服“请假审批 · v1”真实表单运行态通过配置文本核对：页面没有把 `自动计算`、`只读`、`单位天` 或 `单位小时` 当作字段业务值显示。

页面按后台 Schema 渲染了请假类型、开始时间、结束时间、请假天数、请假事由和附件字段。请假天数保持不可编辑，并以“根据起止时间自动计算自然日”作为交互提示；这是字段计算行为提示，不是业务值。审批流程直接在表单下方展开，显示当前流程版本、节点、实际处理人和部门。

本轮只打开表单并读取原生语义树，没有保存草稿、提交审批或修改服务端业务数据。

## 证据

- 原生语义树中原始组合配置值（如 `自动计算，只读，单位天`）命中为 0；唯一相关文本是计算行为提示。
- [当前动态表单截图](../test/evidence/oa-dynamic-config-text-current-20260909.png)

## 代码保护

- 新建/恢复草稿时会清除只读字段中的历史配置文本。
- 详情页会过滤配置 Map 及组合配置字符串。
- `durationUnit`、起止字段引用和计算配置由 Schema 元数据驱动，不使用硬编码表单值。

## 边界

当前仅证明请假审批 v1 的 Android 运行页面；其他后台模板仍按其各自发布 Schema 渲染。服务端节点 `completionMode` 与 `return` 权限语义继续保持未通过状态。
