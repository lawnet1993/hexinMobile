# 774 · 移动端 OA 退回权限发布链路实测

> 日期：2026-09-06，Asia/Shanghai  
> 结论：**未通过**。后台已在 AI-UAT 流程中启用并发布“退回”，真实负责人待办仍未获得 `return` 操作权限，因此本轮没有绕过权限直接调用退回接口。

## 测试数据与范围

- 流程：`AI-UAT-退回验收-20260906-103600`，v1。
- 生效部门：牛牛；部门独立版本。
- 申请：`OA-20260906-486F9A`。
- 发起人：牛牛运营助理；真实处理人：牛牛负责人。
- 表单字段：`退回事由`，值使用 `AI-UAT-` 前缀。
- 仅创建和处理本轮测试数据，没有修改已有流程、已有申请或正式账号。

## 真实执行过程

1. 管理后台新建流程，路径为“申请人 → 部门负责人审批 → 结束”。
2. 审批节点使用“申请人部门负责人”解析规则，并同时启用“转交、加签、退回”。
3. 流程校验通过，v1 发布并应用到牛牛部门；部门绑定页显示“本部门自定义 / 仅本部门 / 已配置”。
4. 牛牛运营助理在移动端打开真实动态表单，审批路径正确解析为“牛牛负责人 · 牛牛”。
5. 提交成功后生成独立申请 `OA-20260906-486F9A`，申请状态为“审批中”。
6. 切换牛牛负责人账号，工作台即时出现 1 条待办；详情显示“待你处理”，实际处理人为 `niu_head`。
7. 打开“更多操作”，只显示“转交、加签”，没有“退回”。

## 判定依据

- 移动端详情页只会从服务端 `allowedActions` 中筛选 `transfer`、`add_sign`、`return` 等操作；代码已经包含 `return` 的入口、原因抽屉和提交调用。
- 同一个真实待办能显示“转交、加签”，但不能显示“退回”，说明移动端已正常消费操作权限列表，当前运行实例没有拿到 `return`。
- 后台发布证据又明确显示该节点已启用“退回”。因此问题位于“流程设计配置 → 发布版本/运行实例 → 待办 `allowedActions`”链路，而不是移动端按钮样式或页面遗漏。

## 影响

- 管理员认为流程已允许退回，但审批人无法执行，配置与实际运行不一致。
- 退回后的目标节点、历史记录、通知、再次发起和幂等语义均无法继续验收。
- 在运行实例真正下发 `return` 前，不能把 OA 退回边界判定为通过。

## 服务端排查提示

请针对流程 v1 和申请 `OA-20260906-486F9A` 核对：

1. 发布快照是否保存了审批节点的 `return` 能力，而不只是设计器草稿保存成功。
2. 创建运行实例时是否把节点能力复制到实例节点/任务权限。
3. 待办详情接口计算 `allowedActions` 时是否把申请人节点视为可退回目标。
4. 如果首个审批节点按产品规则禁止退回，应在管理后台禁用该勾选项并说明原因，不能允许发布后静默丢弃。
5. 修复后返回的 `allowedActions` 应包含 `return`；再由移动端执行一次真实退回，核对目标节点、原因、处理记录、申请人通知和原申请保留。
