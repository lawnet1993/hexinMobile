# 779 · 多设备真实在线状态与离线 TTL 复验

> 日期：2026-09-06  
> 结论：群聊头部在线人数来自真实设备心跳与 `presence.changed` 同步，不是静态文案；前台恢复和离线失效均通过。当前测试服的离线失效窗口约为 2 分钟，产品上应理解为“近期在线状态”，不是进程停止即刻离线。

## 场景

- 沿用三成员测试群 `AI-UAT-MULTIVM-20260906-1100`，不发送消息、不创建或修改业务数据。
- 一台测试端保持停止，另外两台 Android 测试端前台运行。
- 观察端始终停留在群聊页，使用页面语义树和截图读取“成员数 / 在线人数”。

## 结果

1. 第二台测试端恢复前台并完成心跳后，群头部从“3 位成员 · 1 人在线”变为“3 位成员 · 2 人在线”。
2. 强制停止第二台测试端并确认进程消失后：
   - 约 40 秒：仍为 2 人在线；
   - 约 80 秒：仍为 2 人在线；
   - 约 125 秒：自动回落为 1 人在线。
3. 重新启动第二台测试端，观察端在约 26.7 秒 UI 观测上界内恢复为 2 人在线。
4. 两端日志未发现应用 FATAL、ANR、OOM 或 Flutter 未处理异常。

这里的 26.7 秒包含反复生成 UIAutomator 语义树的时间，不能解释为纯心跳或事件网络延迟。离线回落的三次观测也只能确定失效位于约 80–125 秒之间，不能据此断言精确服务端 TTL 值。

## 判定

- 在线人数随另一设备上线变化：**通过**。
- 停止心跳后自动离线：**通过**。
- 前台恢复立即重建在线状态：**通过**。
- “实时”语义：**有明确 TTL 边界**。测试服不会在进程停止瞬间离线，约两分钟内可能仍显示在线。
- 真机锁屏、系统杀进程、厂商省电策略下的状态失效：**尚未通过**；当前 realme 仍锁屏，不能由模拟器替代。

## 产品建议

- 继续显示真实状态，但联系人列表的文案应保留“在线 / 最后在线”，不要写成能保证秒级准确的“当前连接中”。
- 若产品要求 30 秒内离线，需要服务端缩短 presence TTL 或增加显式下线事件；仅调整移动端文案或本地计时不能保证多端一致。
