# 599 应用内通知来源边界与移动端实机交互复核

## 当前结论

已直接操作当前运行并登录的桌面端 `v1.0.80`，进入真实“通知中心”读取页面结构与当前列表。桌面端此入口是应用内统一通知流，同时承载 IM 消息提醒、审批、考勤和在岗巡检等业务事件；它不是 Android/iOS 的系统通知权限或系统设置页。

移动端继续保留与桌面一致的“全部 / 未读”统一时间流，不拆成互相割裂的页面；每条通知新增紧凑来源标签和对应图标色，明确区分群聊、单聊、好友、审批、考勤、巡检、公告、安全及其他应用事件，未知业务事件统一显示“应用”，不再无标签地被误解为“系统通知”。

## 桌面端真实核对

- 当前桌面客户端：`v1.0.80`；账号为老王。
- 页面标题为“通知中心”，当前真实计数为全部 34、未读 25。
- 同一时间流内可见 IM 单聊/群聊提醒、考勤异常、审批撤回、待审批、审批进度与在岗确认等事件。
- 页面只提供“全部 / 未读”筛选，并没有把这些业务事件称为手机系统通知。
- 本轮只进入并读取页面，没有点击通知条目、全部标为已读或其他会改变线上通知状态的操作。

## 移动端实现

- OA、IM 会话和好友申请继续按真实事件时间聚合，保持与桌面统一入口一致。
- 来源标签补齐为：`群聊 / 单聊 / 消息 / 好友 / 审批 / 考勤 / 巡检 / 公告 / 安全 / 应用`。
- 标签使用小号浅色底，不增加说明卡片；列表行仍为紧凑单行标题、单行摘要、时间和未读点。
- 图标色按业务来源区分；紧急程度仍通过未读背景、未读点和现有重要性数据表达。
- 不再把空 `targetKind` 的全部 OA 通知强制改写为 `oa_approval`，避免安全、公告等后续通知被错误归类和跳转。
- 考勤、巡检、审批、好友申请、单聊和群聊原有真实路由保持。
