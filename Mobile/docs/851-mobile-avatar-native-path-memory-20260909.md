# 851 · 头像原图原生路径裁剪内存优化

时间：2026-09-09（Asia/Shanghai）  
范围：Flutter Mobile / 自定义头像

## 修复

Android/iOS 系统选择器能够提供应用可读的临时文件路径时，头像原图先通过原生采样编码缩至最长边 1600 px，再把应用私有的中间图交给裁剪器；不再在裁剪前把最高 80 MB 的源文件完整复制到 Dart 堆，也不再让裁剪器直接解码手机原始分辨率。平台无法提供路径时才使用字节读取回退。

原生裁剪输出仍限制为 768×768，然后执行头像用途的本机压缩；上传协议继续只承载裁剪后的小图片，不影响头像库选择。

## 权限边界

- Android 使用系统文件/照片选择器的一次性 URI 授权，不申请整库读取权限。
- 当前 file_picker Darwin 实现使用 `PHPickerViewController` 选择图片，普通文件使用 `UIDocumentPickerViewController`。
- 用户取消选择时保持原页面；授权在读取前被撤销时继续使用现有明确错误提示。

## Android 真实内存复测

- 样本：6000×4000 JPEG，2,383,565 bytes。
- 直接把原图路径交给 uCrop 时：基线 PSS 187,819 KB，峰值 291,679 KB，增量 103,860 KB。
- 增加裁剪前原生采样后：基线 PSS 186,443 KB，峰值 210,029 KB，增量 23,586 KB。
- 峰值增量下降约 77%，裁剪器成功打开；取消后应用仍存活，应用缓存中未发现 `avatar-crop-input`、`mobile-image-source` 或 `image_cropper` 残留。
- 公共相册和电脑端测试图片均已清理。
