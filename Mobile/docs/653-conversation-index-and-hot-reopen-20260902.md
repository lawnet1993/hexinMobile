## 1. 同账号消息发现

此前根据未读总数差异才重取 bootstrap，不能发现同账号桌面发送但没有增加未读的消息。本轮只读实测 `/api/im/conversations?take=50` 返回 HTTP 200、4 个会话，具有末消息序号、已读序号、未读数、@我序号字段。19:56:19 再次核对仍为同样四个会话。分页候选 `/api/im/conversations/page?page=1&pageSize=50` 返回 405；没有尝试其 Allow 中的 DELETE，也没有假设分页可用。响应没有请求编号。

客户端使用实际可用的 `/api/im/conversations` 列表，不再用未读总数作为发现更新的唯一门槛：

- 事件批次未满 500 条时，以 25 秒最小间隔校对轻量会话列表；追赶满批事件优先，不反复加载大通讯录。
- 相同登录会话合并在途请求，显式刷新可绕过时间间隔；切换或退出后的旧响应不写缓存。
- 在 SQLite 事务中只合并返回的会话，不删除列表未返回的会话、不覆盖成员目录；旧末序号/旧已读序号不能回退本地状态。
- 内容相同不写入、不失效 UI；新末序号产生 652 的持久补齐任务，随后补正文。不伪造事件 ACK、未读或已读。
- 拒绝空 ID、重复 ID、未知类型和错误结构；网络失败保留本地数据。
- Profile 日志仅输出 HTTP 状态、条数、是否变化；不输出账号、正文、令牌、设备指纹或附件地址。

9 项测试覆盖同账号消息/未读零、局部列表合并、过期摘要、账号隔离、并发合并/限频/强制刷新、账号切换、退出、空列表、错误结构、重复 ID、503。索引能力和实际新消息跨端到达是不同验收层次；本轮没有用 API 代替桌面真实发送。

## 2. 热重开跳到旧消息

旧 653 包真机首次打开目标群显示序号 85，返回列表立即重开却显示 `CACHE-003` 起的旧记录。见 [修复前截图](../test/evidence/im-conversation-index-20260902/03-m1-group-reopened.png)。

根因：消息窗口保留 30 分钟，重开时已经是 `AsyncData`；页面监听只响应之后的数据变化，没有消费已有快照，新建 ListView 留在最上方。与服务器是否恢复无关，也不是头像分组合并造成的。

修复：仅在消息页尚未首次定位且没有搜索条件时，从已有消息快照安排布局后的首次定位；保留原异步监听、历史锚点与滚动规则，不清缓存、不重复请求正文。

新增测试走真实 Navigator 入栈、返回、重新入栈和真实保留型消息 Provider；80 条不等高消息，单聊/群聊分别连续打开三次。修复前第二次打开失败，修复后全部定位最新，正文加载次数仍为 1，历史加载为 0；手动滚到旧记录再触发数据刷新，滚动位置保持。聊天专项 **44/44**。现有头像、已读、上滑历史、单群边界测试继续通过。
