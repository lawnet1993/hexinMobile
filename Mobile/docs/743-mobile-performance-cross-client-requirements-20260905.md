# 743 · 移动端性能优化与跨端配合清单

日期：2026-09-05（Asia/Shanghai）

## 目的与边界

本文用于跟踪移动端性能优化中确实需要服务端或 Windows 桌面端配合的事项。移动端能够独立解决的启动、缓存、流式文件、组件重建和内存回收问题，不转嫁给其他端。

当前已确认：小会话热打开、长历史窗口索引、消息解码复用、头像按显示尺寸解码和通讯录可见区域渲染已经落地；最新改动完成后仍需用正常 `lib/main.dart` 的 Profile 包在真机重新测量，Debug 包不能作为性能结论。

2026-09-06 的渲染器控制变量复验进一步确认：同一 Android 16 AVD、同一 80 条消息窗口，SwiftShader 冷开最新消息布局为 719.0 ms、最大 Raster 为 551.6 ms；切换宿主 RTX 4070 GPU 后分别降至 122.8 ms 和 33.8 ms，20 次热开最新消息布局 P50/P95 为 80.2/102.1 ms。此前模拟器长帧主要被软件渲染放大，不能据此缩减消息窗口；物理真机仍需解锁后验证，详见 [769](769-mobile-chat-renderer-isolation-20260906.md)。

### 2026-09-05 23:09 真机 Profile 复测进展

最新媒体说明、点击下载进度、端内视频和音频播放改动已使用正常 `lib/main.dart`、arm64 Profile 包覆盖安装到 realme Android 14 真机，并保留原账号、消息和 OA 数据完成复测：

- 最终包移除工作台自动 TUN 同步后，五次干净冷启动均为 COLD，`TotalTime` 685—714 ms，中位数 700 ms。
- 通讯录头像进入已有 10 条消息的单聊：新进程首次末条消息布局 107.853 ms；同一进程五次热重开 61.351—82.439 ms，均命中消息热缓存。
- 缓存视频连续打开/关闭 10 次，PSS 峰值 273,052 KiB，静置 10 秒后较初始增加 945 KiB，没有短时线性增长证据。
- 真实关闭 Wi-Fi 与移动数据后冷启动仍保留登录态，缓存视频可端内播放；测试结束按原状态恢复网络，关键崩溃、ANR、Unhandled Exception 和 `E/flutter` 为 0。

证据与边界见 [746-mobile-profile-media-performance-real-device-20260905](746-mobile-profile-media-performance-real-device-20260905.md)。510+ 真实长历史、30 分钟内存曲线、未缓存大视频弱网/取消恢复和 iOS 真机仍未完成，不能用本次短时样本替代。

## 移动端独立处理，不需要跨端修改

1. 普通 IM/OA 启动链路移除不使用的 TUN、托管浏览器同步和相关轮询。
2. OA 待上传附件从内存/Base64 草稿改为账号及环境隔离的加密文件引用，并以流式 multipart 上传。
3. 本地选择视频直接按文件路径生成封面，不读取整个视频到内存。
4. 通讯录搜索防抖、组织树投影缓存、IM Provider 细粒度失效。
5. 响应系统内存压力，回收非活动会话、解码图片和视频预览缓存。
6. 真机 Profile 验证冷启动、联系人到会话、510+消息持续滚动、大图/视频、前后台切换、弱网恢复与30分钟内存曲线。

OA 附件第 2 项的代码、自动化、小图片草稿恢复，以及 19 MiB 普通文件的真机选择、覆盖升级、打开和清理已经完成。共享测试服真实 multipart 提交、弱网补传、服务端摘要核对和桌面端回读仍未完成，因此当前继续标记未通过；证据和通过门槛见 [747-oa-attachment-binary-stream-verification-20260905](747-oa-attachment-binary-stream-verification-20260905.md)。

IM、OA、图片、音视频与头像的上传方式和未完成验收矩阵见 [748-mobile-upload-transport-audit-20260906](748-mobile-upload-transport-audit-20260906.md)。除用户确认可保留的小头像 Data URL 外，大文件正文不得写入 Base64 或业务数据库。

2026-09-06 新增远端媒体下载文件流：视频/音频首次播放不再先把完整响应收进 `Uint8List`，而是直接写 `.part`、以文件流校验 SHA-256 后原子重命名。102 项相关测试通过，arm64 Profile 包覆盖安装后，真机移走单项视频缓存可重新下载相同大小和摘要并播放。弱网可见进度、取消/恢复和音频缓存未命中仍未通过真机验收，证据见 [751](751-mobile-media-stream-download-real-device-20260906.md)。

2026-09-06 更新前的桌面缓存缺消息与日志异常见 [749](749-windows-im-sync-live-finding-20260906.md)。升级至 v1.0.94 后，Computer Use 与真机实操已确认旧文件补齐、本轮新文本双端可见、手机回复在桌面原会话自然出现；但桌面摘要至少 86 秒未更新、指定历史视频点击播放 404 真实复现。手机清除该单项缓存后可重新下载并播放同一对象，因此应优先检查桌面对象 ID、路由和鉴权。手机群聊发送与单聊边界已补一个样本；桌面群聊自然接收、跨账号双端已读与离线补偿仍未重测。最新截图及提示词见 [750](750-windows-1094-real-window-regression-20260906.md)，更新前失败不直接沿用到新版。

## Windows / Gateway 历史异常与当前待复验项

### P1：桌面入站同步历史失败，升级后 v1.0.94 复验中

2026-09-05 的 740/741 测试记录显示：手机发送的消息写入服务端，并可被另一台移动设备通过事件流接收、落库和 ACK；当时检查的 Windows 本地 SQLite 缺少相同消息，日志长期停留在 `connecting -> transport error -> retry-wait`，未观察到 `connected/event received/ACK`。上述为当时采样结果，不代表 v1.0.93 已完成同样的窗口复验。

完整证据、消息序号、请求编号和可直接交给桌面端 AI 的提示词见：

- [740-current-desktop-inbound-sync-current-reproduction](740-desktop-inbound-sync-current-reproduction.md)
- [741-mobile-sync-health-and-desktop-gateway](741-mobile-sync-health-and-desktop-gateway.md)

桌面端修复不能依赖用户打开会话时临时 GET 历史来掩盖事件缺口，必须处理连接、事务落库、游标、ACK、幂等和缺口补偿。

## 建议服务端提供，需先确认现有能力

以下是性能协议需求，不在尚未确认服务端现状时直接判定为缺陷。

### P1：媒体缩略图与视频封面

当前客户端在远程视频没有封面时，可能需要下载完整视频后生成缩略图；图片列表虽按显示尺寸解码，但若服务端只提供原图，网络流量和原始字节内存仍然存在。

建议服务端：

1. 图片和视频上传完成后异步生成服务端缩略图/封面，并在消息或附件元数据中返回稳定的 `thumbnailObjectId` / `coverObjectId`。
2. 提供按目标宽高或固定规格获取缩略图的接口，优先 WebP/AVIF，保留原图下载入口。
3. 缩略图返回 `ETag`、`Cache-Control` 和内容摘要；同一附件跨 IM/OA 使用一致缓存语义。
4. 视频与大附件下载支持 HTTP Range、取消和断点续传，避免预览必须读取完整对象。

验收：进入含10张大图和3个视频的会话时，未点击原图/播放前不得下载完整视频；重复进入不重复下载未变化缩略图；取消页面后请求及时终止。

### P2：通讯录增量和服务端分页

移动端已对2000人列表做组件虚拟化，但当前组织目录仍可能整包获取。若生产组织达到一万级以上，仅优化 Flutter 行组件不能消除网络、JSON解析和内存成本。

建议服务端提供：

1. 部门树独立接口，只返回层级、人数与版本号。
2. 点击部门后按 `departmentId + cursor + take` 分页获取直属成员。
3. 搜索使用服务端索引并分页，不能要求客户端先下载全员再过滤。
4. 组织、成员、岗位和在线状态使用版本号或增量事件更新，避免每次事件重新拉整份目录。

验收：1万、5万账号组织下，首页不下载全员；展开一个部门只获取该部门页面；滚动继续自动分页；成员变更后只更新相关部门，账号、在线状态和群聊数据不串。

### P2：同步健康指标落盘与告警

移动端心跳已经上报 IM/OA 的传输模式、已应用游标、已 ACK 游标、待发送数量和健康状态。服务端仍需确认 DTO、存储、指标面板与告警是否消费这些字段。

验收：后台能按平台和版本查看 `transportMode`、`cursorLag`、`pendingAckCount`、OA待发送数和最近成功时间；连续异常产生聚合告警，但不记录账号、Token、设备指纹、消息正文或附件地址。

## 交给服务端 AI 的提示词

```text
你负责核对并补齐 SecureAccess 测试服的移动媒体与通讯录性能协议。不要修改移动端本地缓存语义，不要输出密码、Token、Cookie、设备 ID、指纹、消息正文或附件真实地址。

先用当前线上接口和服务端源码确认现状，不要把建议当成已存在能力：
1. 核对 IM 图片、IM 视频、OA附件上传后是否生成缩略图或视频封面，消息/附件元数据是否稳定返回 thumbnailObjectId/coverObjectId。
2. 核对缩略图接口能否按规格返回 WebP/AVIF，是否有 ETag、Cache-Control、内容摘要；大附件和视频是否支持 HTTP Range、取消与断点续传。
3. 核对组织通讯录是否只能整包返回；若生产规模达到一万级，实现部门树版本接口、按部门 cursor 分页、服务端搜索分页和成员/部门增量事件。
4. 核对 /api/client/heartbeat 已接收的 imSync/oaSync 字段是否真正进入指标存储和面板，建立不含敏感数据的 cursor lag、pending ACK、待发送数和最近成功时间告警。

输出：现有接口与代码位置、缺口、兼容方案、迁移顺序、请求/响应示例、数据库或对象存储影响、灰度和回滚方案、自动化测试及压测结果。验收必须证明列表预览不下载完整视频、重复打开命中缓存、Range可取消恢复、1万/5万组织不整包下载、同步健康异常可在后台定位。
```
