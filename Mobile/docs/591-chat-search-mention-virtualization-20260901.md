# 591 会话搜索与大群提及成员性能整改

## 当前结论

本轮同时修正会话内搜索密度和大群 `@成员` 选择器的构建性能。

- 会话内“搜索聊天记录”从默认大输入框改为 34dp `MobileSearchField`，关闭按钮独立为 34×34dp。
- `@成员` 选择器改为覆盖底部 Tab 的根导航抽屉，使用 34dp 搜索、50dp 成员行和 17dp 头像。
- 成员行展示真实姓名、部门、账号和在线状态。
- `@全体` 继续同时受群资料 `atEnabled` 与消息配置 `mentionAll` 控制，不扩大权限。
- 原实现用 `members.map` 一次创建全部成员组件；现在使用 `ListView.builder` 只构建可见行，搜索后再构建匹配成员。

当前判定：**实现、自动化、静态检查、构建和覆盖安装通过；真机触控复验待正常解锁**。

## 大群性能证据

新增自动化构造 2001 人群：

1. 打开提及成员抽屉后，第 1999 名成员的组件不存在，证明未预先构建全部列表。
2. 首屏 `ListTile` 构建数量小于 40。
3. 输入精确账号 `large1999` 后，目标第 1999 名成员才出现。
4. 搜索框为 34dp、成员行为 50dp，默认不主动弹键盘。

这证明成员选择已经从 O(n) 首屏组件创建改为视口懒构建；过滤仍需要线性扫描成员数据，但不会一次构建 2000 个 Flutter 行组件。
