## 问题与修复

### P1：新环境 OA 附件上传返回 HTTP 500，未解决

复现：test01 → 请假审批 → 填有效年假/起止时间/AI-UAT 事由 → 添加上面的 176 B txt → 提交 → 待同步 → 重试。

预期：附件上传成功、表单提交产生编号；暂时失败时保留本地文件并可恢复。

实际：上传阶段 HTTP 500，带附件申请不能进入服务端流程；同账号同模板无附件对照可成功提交、审批、撤回和驳回。

影响：新环境 OA 附件链路不可验收。500 的服务端内部根因仍需后端日志，不凭此认定是存储配置、网关还是服务实现错误。

证据：21、40、42。移动原始 HTTP request ID 未采集；只读核对响应也未提供请求编号（null），不伪造编号。错误摘要只保存操作阶段与状态码，不保存原始响应正文。

### P2：暂时失败的待同步申请没有原因/重试入口，已修复并实测

原复现：上述提交进入 pending 后，只显示“待自动同步 · 1 次”，点击记录无效果（16–17）。原因与操作只给 failed 永久失败记录展示。

修复：pending 有失败信息时也显示紧凑的一行摘要和“同步操作”；底部抽屉提供重试与查看同步原因。重试沿用原队列项和请求标识，不新建一条。暂时失败不提供“放弃记录”或“修改后重提”，避免在服务器是否收件不明时丢记录或换标识重复提交。永久表单校验错误保留原有修改流程。

同时把暂时错误持久化为安全的“附件上传/申请提交 + HTTP 状态”摘要，不保存代理响应正文；旧错误若含 URL、token、Cookie、Authorization 或堆栈信息，UI 回退为安全短提示。具体表单校验消息仍保留。此修复并未修好服务端 500。

代码：`todos_page.dart`、`collaboration_repositories.dart`。测试：`oa_mobile_pages_test.dart` 新增 pending 操作和旧错误脱敏用例；`oa_offline_attachment_submission_test.dart` 验证 503 摘要不泄露响应正文、附件续传后继续原申请。
