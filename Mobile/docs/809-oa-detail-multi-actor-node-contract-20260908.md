# OA 详情多人审批节点契约缺口（2026-09-08）

## 现场发现

在 realme 真机打开真实待办 `OA-20260908-AFB60B`，审批进度中连续出现三条同名“部门负责人审批”：

- Test Terminal 01：待你处理；
- 陆炳002：待处理；
- 陆炳：已同意。

三条记录很可能属于同一多人节点，但当前移动端详情模型只能取得每个任务的 `nodeId`、`stage`、处理人和任务状态，没有取得该节点的审批完成规则。界面因此只能逐任务展示，无法可靠说明它是会签、或签、依次审批还是其他规则。

## 为什么不能只在移动端猜测

- “同一 `nodeId`/`stage` 有多人”只能证明多人参与，不能证明必须全部同意。
- 一人已同意、其余仍待处理通常符合会签，但也可能是尚未完成的其他策略。
- 或签完成后其余任务应取消；仅凭当前任务状态推断会造成历史详情前后不一致。
- 审批方式属于后端流程定义和运行实例事实，客户端不应根据人数或状态猜测。

## 服务端建议

为 `GET /api/oa/approval-requests/{requestId}` 的任务或节点视图增加稳定字段，推荐按节点返回：

```json
{
  "nodeId": "...",
  "stage": 1,
  "nodeName": "部门负责人审批",
  "completionMode": "all",
  "approvalModeLabel": "会签",
  "tasks": []
}
```

如果暂时继续返回扁平 `tasks`，则每条任务至少补充一致的：

- `completionMode`: `all` / `any` / `sequential` / `single`；
- `nodeType`；
- `actorCount`；
- 可选 `completedActorCount`。

字段语义应与发起页流程预览中的 `OaWorkflowPreviewNode.completionMode` 一致，避免预览与详情使用两套规则。

## 移动端收到字段后的展示

1. 按 `stage + nodeId` 合并同一运行节点，只显示一次节点标题。
2. 标题旁显示“会签”“或签”“依次审批”等短标签。
3. 节点下紧凑列出实际处理人、部门和各自状态。
4. 会签显示 `已完成人数/总人数`；未全部同意前不得把节点标成完成。
5. 或签完成后，其余被取消任务显示为“无需处理”，不得继续表现为可操作。
6. 转交、前加签、后加签任务仍保留来源关系，不能仅因同名而错误合并。

## 本轮已通过的移动端部分

- 真实补卡字段只显示补卡时间和原因，没有暴露内部异常 ID。
- 审批进度直接在详情页展开，不是弹窗。
- 处理人显示头像、姓名和部门，没有显示登录账号。
- 底部“更多/驳回/同意”按钮为 34dp 紧凑尺寸。
- “更多操作”和“选择加签人”均使用向上展开的底部抽屉。
- 加签成员选择器隐藏账号，仅显示姓名与部门。
