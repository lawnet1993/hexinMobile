# 666 OA 网络唤醒、生命周期与真实恢复验证

时间：2026-09-02，完成验证于22:53（中国时间）。本轮有代码与真实运行进展，完整移动端 IM/OA 目标仍在进行中。

## 原因与修改

665 实测恢复网络后约28秒才观察到目录更新。原 OA 协调器未订阅系统网络变化；前台唤醒只取消上一轮长轮询，下一轮仍使用20秒等待，没有立即刷新工作区。另外，启动阶段尚未保存运行任务，停止操作无法等待该阶段结束，旧请求完成后可能继续发出状态回调。

修改 `oa_catalog_sync_coordinator.dart` 与 OA 仓库：

- 订阅网络接口变化；离线显示不可用，联网仅作为唤醒信号，不直接宣告服务恢复。同样的接口事件合并。
- 恢复网络或回到前台后取消旧读取，重新获取并持久化 bootstrap、应用目录与通知页，随后失效相关 UI 缓存，再报告可用。
- 首次及恢复后事件请求采用 `waitSeconds=0`，有新事件时连续追赶；追平才恢复20秒长轮询。仓库默认参数仍为20秒。
- 启动时即记录运行任务；使用代次检查隔离快速停止/重启。取消令牌覆盖工作区读取与事件查询，阻止已取消读取继续提交缓存。
- 3秒失败退避可被网络恢复或停止唤醒。反复同类联网通知不会将持续503变成“已连接”，也不会产生紧密请求循环。
- 复用已实现的账号、完整会话身份检查；本轮没有更改业务公式、流程配置或服务端。
