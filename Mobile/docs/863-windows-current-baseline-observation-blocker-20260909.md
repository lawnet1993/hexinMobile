# 863 · 当前 Windows 桌面基准观察边界

时间：2026-09-09（Asia/Shanghai）

## 已确认事实

- 用户提供的当前桌面运行截图右下角显示客户端版本 `v1.0.105`，工作台包含受控站点、日程、公告、常用应用和待办列表。
- 当前机器存在运行中的 `hexing-zhilian`、remote agent 和 remote service 进程。
- 运行中 shell 的文件路径为本机安装目录；PE 文件元数据仍报告 `1.0.87`，与页面显示的前端/发布版本 `v1.0.105` 不一致。二者应分别记录，不能用 PE 元数据否定页面版本，也不能把页面版本冒充为 shell 二进制版本。

## 本轮阻塞

按 Computer Use 技能初始化 Windows UI 控制时，首次、重试以及重置会话后的最后一次均返回：

`failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`

技能恢复规则要求停止继续输入，不能改用自制 UI 自动化绕过。因此本轮没有点击或修改 Windows 客户端，也没有把旧源码或旧截图当成当前功能证据。

2026-09-09 后续复验时，统一电脑控制运行时已经能够初始化并返回状态，但只暴露 Codex 应用内浏览器，原生 `apps` 列表为空，没有返回可绑定的合兴智联窗口。按同一安全规则，未构造窗口句柄、未复用旧坐标，也未使用 PowerShell UI Automation 绕过。由此可确认阻塞已从“运行时无法初始化”收敛为“当前会话没有开放 Windows 原生应用表面”，桌面客户端仍不能在本轮直接操作。

2026-09-09 当前最终 Android 构建完成全量回归后，再次按 bundled Computer Use 技能规定初始化 `@oai/sky`。首次初始化及一次 kernel reset 后的唯一重试均返回 `failed to write kernel assets: 系统找不到指定的路径。 (os error 3)`，尚未进入 `list_apps` 阶段。此后停止重试；没有启动自制 helper、没有通过终端驱动 Windows UI，也没有把移动端结果替代为桌面端可见窗口证据。

## 对移动端验收的影响

- 可以继续使用已提供的 v1.0.105 工作台截图作为有限视觉参考。
- 当前桌面窗口逐项操作、最新 IM 媒体行为和桌面到移动实时同步仍需在 Windows UI 控制恢复后重新验证。
