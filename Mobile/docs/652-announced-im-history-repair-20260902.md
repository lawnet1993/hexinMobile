## 2. 本轮实现

- Bootstrap 与事件事务更新时，根据服务端已公布的会话末序号，登记独立的历史补齐任务，按账号和会话隔离。
- 使用既有 history GET，按 beforeSequence / take=50 从已知新末端向旧缓存接合点分页；每轮最多处理三个任务页，期间让出事件轮询和发送机会。事件满 500 条时优先追赶事件。
- 每一页正文与下一页位置在同一 SQLite 事务提交；应用退出后继续该位置，不能因为已拿到最新一页就漏掉中间页。补齐期间有更高末序号时保留当前区间，完成后继续新区间。
- 本地事件已完整落下相同区间时，不再请求历史，也不重复刷新消息 UI；有真实正文变化时只失效对应会话的缓存。
- 历史补齐状态与事件 cursor / ACK / lastRead 分离。只读历史不会发已读请求，不清除未读或 @我，不伪造事件序号。
- 请求固定原会话凭据；返回后再次核对会话。账号切换/退出的迟到结果不会写进另一个账号。拒绝其他会话、超出分页范围及无有效 ID 的响应。
- 首次空页不作为已补齐证明；503、格式错误保留任务，30 秒后再试。取消、401/409 交给既有会话与生命周期处理。
- 本地清空会话时一并取消其补齐计划，旧请求的比较提交失败，不能把已清空正文重新写回。

无缓存的新安装仅预取最新 50 条，更早历史保持上滑分页；已有缓存的断线缺口从其原末端接续。不会宣称新安装已离线保存所有历史，也不以该机制替代服务端可靠事件分发。

主要文件：`im_local_store.dart`、`collaboration_repositories.dart`、`im_sync_coordinator.dart`、`collaboration_client.dart`。
