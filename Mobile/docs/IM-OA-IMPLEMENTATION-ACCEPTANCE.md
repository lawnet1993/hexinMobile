# 移动端 IM / OA 实现与验收记录

日期：2026-08-24

## 参考基线

移动端以 `Desktop/Windows` 的登录态、IM/OA 接口路径、权限字段和数据模型为契约基线，不复制桌面布局；交互按手机单列页面、底部主导航、抽屉/底部弹层和触控尺寸适配。

## 已完成闭环

### IM

- 登录后加载会话、联系人、组织部门、好友申请、权限及群配置。
- 单聊/群聊创建，会话列表与消息历史，本地 SQLite 缓存。
- 文本、回复、@成员、@全体、附件、联系人名片发送；失败消息进入本地 outbox 并可重试。
- 附件下载、已读上报、增量事件拉取与确认。
- 会话置顶/免打扰/清空；群成员、群资料、角色、移除、转让、退群与解散按服务端权限执行。
- 通讯录搜索、发起好友申请和从联系人进入会话。

### OA

- 工作台应用目录、待办、通知、公告、考勤入口。
- 审批分页与筛选、详情、时间线、抄送已读。
- 基于服务端模板动态渲染申请表单，支持草稿、附件与离线提交队列。
- 同意、驳回及服务端 `allowedActions` 下发的高级审批动作。
- 通知、待办、考勤补卡结果可跳转到对应审批详情。

## 本次修复

登录接口在测试环境返回的协作地址已经带有 `/api/im`、`/api/oa`。Repository 请求路径也包含相同前缀，原实现会形成重复路径并使全部协作接口返回 404。

`CollaborationClient` 现在兼容“仅域名”和“带服务前缀”两种登录响应，将请求统一组合为桌面端/服务端使用的 `/api/im/*`、`/api/oa/*`。测试环境只读契约检查脚本位于 `tool/mobile_collaboration_contract_check.mjs`，配置通过 `ADMIN_TEST_CONFIG` 注入，不写入账号、密码或令牌。

## 验收证据

- `flutter analyze`：通过，无问题。
- `flutter test`：57 项通过；覆盖导航、IM 会话类型与本地消息、OA 缓存/动态表单/离线附件/审批动作，以及 12 个页面视觉回归。
- 测试环境只读接口：登录、IM bootstrap、OA bootstrap、OA 应用目录、通知、审批分页均返回 HTTP 200。
- URL 归一化：新增 3 项单元测试，覆盖 IM、OA 服务前缀及仅域名三种情况。
- Android 调试包：构建通过，产物为 `build/app/outputs/flutter-apk/app-debug.apk`。

## 边界与运行说明

- 契约检查只读取列表/初始化接口，避免在共享测试环境自动创建会话、发送消息或提交审批产生业务脏数据；写操作由 Repository 测试和页面测试覆盖，人工验收时使用专用测试数据执行。
- 当前交付缺少原生 `secure_tunnel` 包。`Packages/secure_tunnel` 为明确返回 unavailable 的兼容实现，仅用于让 IM/OA 工程可分析、测试和构建；它不会伪造 VPN 已连接。原生隧道能力应由对应平台包恢复后另行验收。
- 含空格和中文的原始工程路径会触发当前 Flutter 工具链路径问题；本次通过映射 `Client` 根目录到临时盘符执行，不改变源码结构。
- Windows 上 Gradle 9.3.1 的既有用户缓存会令标准 Kotlin settings 脚本解析失败；工程提供 `android/settings.gradle` 等价兼容入口，并使用隔离缓存完成构建。

## 人工验收清单

1. 使用测试终端账号登录，确认工作台、消息、通讯录和待办均能刷新。
2. 创建专用单聊，互发文本、附件、回复和联系人名片，确认另一终端收到并展示已读状态。
3. 创建专用群聊，验证 @成员、免打扰、置顶及有权限的群管理动作。
4. 从工作台发起一条测试审批，保存并恢复草稿，再提交。
5. 使用审批人账号执行同意/驳回，确认申请人待办、通知和详情时间线同步更新。
