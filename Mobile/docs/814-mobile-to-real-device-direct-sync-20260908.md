# 814 · 模拟器到真机单聊与群聊实时同步（2026-09-08）

## 结论

Test Terminal 03（Android 模拟器）向 Test Terminal 01（realme 真机）发送唯一单聊消息后，真机在未打开消息页时收到事件并出现 1 条未读；会话列表摘要随之更新。真机打开会话后目标消息只出现一次，返回列表未读清零，发送端自然显示“已有接收人已读”。强制停止并重启真机应用后，目标消息仍只有一条，未读没有回涨。

随后在双方共同群聊中发送第二条唯一消息。接收端停留在此前单聊时，群消息没有混入当前单聊；返回列表后，仅目标群聊显示独立摘要和 1 条未读。打开群聊后，消息只渲染一次并显示发送人，发送端收到已读状态。本轮判定：**跨设备单聊和群聊的实时到达、会话隔离、显式阅读、已读回传、持久化与去重通过**。

## 环境与边界

- 桌面功能基准：用户当前实际运行窗口 v1.0.105；本用例只验证 Android 移动端之间的链路，不替代桌面窗口验收。
- 发送端：Test Terminal 03，`emulator-5556`，当前移动端 v1.0.1。
- 接收端：Test Terminal 01，`dd00d66d` realme 真机，当前移动端 v1.0.1。
- 测试数据：`AI-UAT-M2M-20260908-234016-M3-TO-M1`。
- 群聊测试数据：`AI-UAT-M2M-GROUP-20260908-234951-M3-TO-M1`。
- 未输出密码、令牌、Cookie、完整设备标识或附件地址。

## 实测时间线

1. 模拟器冷启动时发现 DNS 未下发；使用不清数据的冷启动并显式指定解析器后，Test Terminal 03 使用安全存储中的既有凭据登录成功。
2. 登录后心跳返回 204；发送端 IM 健康状态为 `http_long_poll`，游标已应用且已 ACK，待 ACK 数为 0。
3. Test Terminal 03 在与 Test Terminal 01 的既有 direct 会话中发送唯一消息。发送端消息节点显示“已发送，查看已读详情”。
4. Test Terminal 01 保持在工作台、没有打开该会话。事件序号 6052 被拉取、事务应用并 ACK；工作台消息角标从 0 变为 1。
5. 真机进入消息列表后，Test Terminal 03 会话摘要显示唯一消息及 1 条未读。
6. 真机打开会话，目标文本的 UI 语义树匹配次数为 1；随后发送端状态变为“已有接收人已读，查看已读详情”。
7. 真机返回会话列表后，同一行不再包含未读数。
8. 强制停止并重新启动真机应用，再次打开会话，目标文本匹配次数仍为 1；健康日志显示 applied=acked=6054、pendingAckCount=0。

## 群聊边界实测

1. Test Terminal 01 保持打开与 Test Terminal 03 的单聊，Test Terminal 03 在双方共同群 `AI-UAT-20260902-202100-M1-M3-GROUP` 中发送唯一消息。
2. 发送端显示“已发送”；真机当前单聊的语义树不包含该群消息，证明群聊内容没有串入 direct 会话。
3. 真机返回消息列表后，目标群聊摘要更新为本轮消息并显示 1 条未读；对应行仍明确标记为“群聊”。
4. 真机打开目标群聊，消息匹配次数为 1，消息块显示发送人 Test Terminal 03；发送端随后变为“已有接收人已读”。

## 性能与状态证据

- 接收事件：`eventCount=1`，事件序号 6052。
- 本轮长轮询请求在事件提交前已等待约 22.9 秒；服务端事件年龄约 142 ms，说明消息提交后唤醒和移动端事务处理正常，不能把长轮询已等待时间误算为消息端到端延迟。
- 事件处理分段：bootstrap 约 50 ms、commit 约 34 ms、ACK 约 94 ms。
- 阅读事件应用后接收端游标推进至 6054，应用游标与 ACK 游标一致。
