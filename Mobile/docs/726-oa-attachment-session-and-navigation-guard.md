# 726 既有审批附件打开链路的会话与导航隔离

时间：2026-09-05 00:52–01:02，Asia/Shanghai。结论：本轮隔离修正与普通 TXT 系统交接通过；不代表 Office 预览已支持或整体 OA 已验收。

## 复现与修正

P1：附件原件、缩略图和图片预览下载没有在响应后检查会话。通过本机真实 HTTP 服务，在返回前切换账号、重新登录或退出，旧接口仍返回旧字节；旧会话的 500 也未归类为过期响应。新增 12 个回归在修复前全部失败。

- 三种下载共享会话绑定实现：使用发起时的身份，请求前/成功后/异常后校验，迟到响应抛 SessionChangedException；支持调用方明确绑定会话与取消令牌。
- 下载结束释放独立 HTTP 客户端；不修改服务端 API、权限、表单或原附件。
- 详情中单次打开设并发锁，避免双击重复下载/打开。退出详情取消下载；详情被其他路由覆盖、会话变化时，不弹出旧附件或旧错误。
- 已经打开的旧图片在账号变化时移除图像，显示登录状态变化提示。仍是原有图片预览，不是被暂停的新内置文档引擎。
- 普通文件按环境与账号散列目录隔离，每次打开创建唯一子目录，避免同名文件覆盖。未成功交给外部应用的本次临时目录在失败/取消后删除；不会删除既有其他文件。
- 已经交给系统打开的文件暂留私有缓存，避免外部程序尚未读取就被删掉；外部程序已获取的内容不能靠移动端切换账号撤销。长期缓存清理策略仍需另行完善，未宣称已解决所有磁盘保留问题。
