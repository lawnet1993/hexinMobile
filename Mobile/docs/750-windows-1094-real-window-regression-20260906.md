## 手机群聊边界补测

真机 test01 进入既有 `AI-UAT-20260902-202100-M1-M3-GROUP`（2 位成员、1 人在线），发送一条带 AI-UAT 前缀的新文本。消息在群会话中只出现一条，状态为已发送；返回消息列表后，该群的最后消息和时间更新到 00:58，而 Test Terminal 03 单聊仍保持 00:51 的私聊摘要。此样本没有出现群消息写入单聊或单聊摘要被群消息覆盖。

群内历史 `@` 消息的可见文本存在名称与正文交错现象。真机实操确认：成员选择器会在当前光标位置插入提及文本；选择后直接输入并发送时，结构化 `@Test Terminal 03` 能正确加粗且正文顺序正常。若用户随后手动把光标点进提及名称中间，普通文本仍可插入并破坏可见名称；本轮构造的错误草稿在发送前已清空，没有产生错误消息。当前渲染链路不应按历史截图判为失败，但提及编辑仍建议做原子 token 或发送前一致性校验。

## 问题 1：P2，会话摘要未跟随同账号跨端消息更新

复现步骤：桌面 test01 打开 Test Terminal 03；手机同账号向这个会话发送本轮 00:51 消息；保持桌面会话打开，观察聊天区与左侧列表。

预期：聊天区、列表最后消息、列表时间同步更新，自己的消息不增加自己的未读。

实际：聊天区自然出现 00:51 手机消息且仅一条，左侧仍显示 00:48 桌面消息，至少持续 86 秒。最终观测前因外部截图预览遮挡，仅重新激活目标窗口，没有刷新应用或切换会话。影响：列表预览和时间落后；排序是否受影响本轮未覆盖。证据见上述 33 秒与 86 秒截图。

该问题已有 UI 证据；具体事件编号、服务端请求编号、前端状态失效时序本轮未捕获，不臆造根因。

## 问题 2：P2，指定历史视频点击播放报 404

复现步骤：桌面 test01 → Test Terminal 03 → 点击已存在的 `video_fc9a168d-14c5-4f02-8df2-3ec4b5b9bbf0.mp4` 播放按钮（卡片显示 2.0 MB、0:03）。

预期：有效视频应可下载并播放；若对象确实不存在，明确提示附件失效并提供合适处理路径。

实际：桌面出现短暂深色加载层，随后退出，红色提示 `collaboration service request failed: status=404 detail=attachment request failed`。未播放，未唤起系统播放器。手机先命中既有缓存播放成功；随后仅备份并移走该视频的 2,134,392 字节缓存，再次点击同一消息后，移动端从服务端重新生成相同大小、相同 SHA-256 的缓存文件，Media3 初始化视频 AVC 与音频 AAC 解码器并播放到 0:03。手机进程没有本次播放相关的 404、FATAL、ANR 或 E/flutter；验证后已删除临时备份，仅保留新下载缓存。

边界：2 MB 文件在当前网络下下载很快，未捕捉到可见百分比，因此下载进度展示仍未通过真机验收。新包已经把远端媒体从整文件 `Uint8List` 改为直接写 `.part`、流式 SHA-256 校验和原子重命名；详见 751 文档。

影响：该有效历史视频无法从桌面打开。仅确认这一个对象失败，不推广到所有视频或音频。界面暴露底层英文请求错误也需要调整。服务端对象已由手机缓存未命中下载确认存在，桌面请求路由、对象 ID、权限与请求编号仍待核对。
