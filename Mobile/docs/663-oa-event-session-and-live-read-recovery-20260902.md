# 663 OA 同步会话隔离与真实已读恢复

时间：2026-09-02 22:04–22:13（北京时间）。结论：本项局部通过；完整 IM/OA 与桌面功能对齐目标仍在进行。

## 复现与修复

`pullEvents` 最初获取账号后，事件、通知、bootstrap、应用目录和考勤查询分别重新读取当前登录身份，最终按最初账号落库。切号后可能将新账号响应写进旧账号缓存；同账号重登的旧响应也可能覆盖新状态。

本地 HTTP + SQLite 首轮完整复现中，**25 项隔离用例失败，5 项正常/失败原子性对照通过**。覆盖事件及每个后续查询阶段切号、重登、退出，以及目录/考勤/通知独立刷新。初次测试的服务端断言阻止响应收尾，已主动停止该测试句柄并修正测试记录方式，重新完整跑出上述结果。

修改：[协作仓库](../lib/features/collaboration/data/collaboration_repositories.dart)。

- 整批同步以及启动工作区刷新固定使用原始会话，网络前后校验真实会话标识。
- 事件所需数据全部成功后，在当前会话保护下以 SQLite 事务一起提交缓存、事件和游标；取消、中途 500、会话改变时不提交半批结果。
- 目录、考勤、通知独立刷新及缓存未命中回源保留调用时身份；本地缓存读取也受到当前会话保护。
- 旧登录的空事件批次或迟到 HTTP 错误不能被当作新登录的同步结果。
- 保持原通知分页参数及离线已读投影，重复事件不回退游标、不复活已读。
- 会话锁仅用于本地校验/提交，不覆盖网络等待。
