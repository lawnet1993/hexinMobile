# 718 移动端操作按钮收紧

用户要求当前和后续页面均排查过大的操作按钮。本轮优先覆盖 OA 底部操作条与通用选择/输入抽屉，不修改业务规则。

## 后续页面检查标准

- 常规操作采用紧凑文字和内边距，普通按钮可见底色约 34 逻辑像素高，常规文字 13、字重 500、圆角 6。
- 紧凑外观与点击区域分开：保留 44–48 逻辑像素的触控空间，不能仅靠缩小命中区域解决“大按钮”。
- 次要操作优先文字按钮；装饰性发送、保存图标不是必需，避免叠加视觉重量。
- 简短操作不默认 `Expanded` 撑满整行；审批详情操作组靠右，保留清晰的主次和间距。
- 新增或巡检页面时同时检查窄屏、字体缩放、键盘/抽屉、禁用和忙碌态；长操作文案应让布局自适应，不能一刀切固定所有宽高。
- 登录、录音等特定场景按用途评估，不能机械套用所有按钮。未逐页验证的按钮不记为已完成。

## 本次实现

- 通用 `compactMobileActionStyle` 统一可见尺寸、字体、圆角及 padded 触控区域。
- 发起审批：草稿由带边框/图标按钮改为 88 宽文字操作；提交由 140 宽带发送图标改为 104 宽文字按钮，整体点击区域高 48，保留防重复提交及无障碍忙碌说明。第一次真机查看发现外层固定 44 高仍撑大了可见底色，随后移除固定高度并补充真实 Material 高度断言，目标为可见 34 / 点击 48。
- 审批详情：更多/驳回/同意不再铺满宽度，图标 16；再次发起靠右。可见按钮高 34，触控高 48。
- 通用多选确认、信息确认、确认/取消、文字输入提交、日期时间确认采用同一紧凑样式；危险操作的颜色和验证门槛不变。
- 新增 3 个控件测试，分别覆盖 Filled/Outlined/Text 的 34 高可见表面、48 高触控区，并真实点击透明留白验证回调。
- 更新原有审批 UI 测试，分别检查可见 Material 高度和触控高度，未放宽成无尺寸约束。
- 审批详情 golden 因用户明确要求的按钮宽度和布局变化而更新；更新前已人工查看新旧图，未批量重录其他页面基线。
