# 584 选择器与补卡表单移动端真机验收

## 结论

本轮统一了外观/语言选择器，并重新压缩了真实补卡表单。移动端选择、日期、时间和表单操作继续从底部展开，不使用居中弹窗。

- 主题模式、账号语言、通知锁屏内容复用同一 `MobileChoiceSheet`。
- 选择抽屉统一使用根导航、安全区、选中标记和 48dp 选项行。
- 补卡表单改为覆盖底部区域的紧凑抽屉，标题、关闭、时间、原因和操作区层级清楚。
- 补卡时间按钮、取消和提交按钮均不超过 40dp；提交按钮宽度小于 120dp。
- 补卡原因使用浅灰无描边输入区，不再使用突出的默认大号轮廓输入框。
- 日期和时间继续使用统一底部选择器，保持真实考勤字段与业务规则不变。

本轮范围判定：**通过**。

## 外观与语言选择

旧实现由设置页维护独立的 `showModalBottomSheet` 列表，样式和根导航行为容易与表单、筛选选择器分叉。

现在主题模式、账号语言和通知隐私均调用共享选择抽屉：

- 标题、关闭入口、选中图标和行高一致。
- 自动覆盖当前导航层和安全区。
- 当前值作为真实选中项显示。
- 本轮只打开“主题模式”后关闭，没有改变浅色主题或账号语言。

## 真实补卡页面

通过真实通知中心的既有考勤异常进入补卡页，服务端返回：

- 本月异常：19 条。
- 本月补卡次数：0/3。
- 首条异常：2026-08-31 缺上班卡。

打开第一条异常的补卡表单后验证：

1. 抽屉标题为“补缺上班卡”。
2. 默认时间为 `2026-08-31 00:00`。
3. 时间入口为 36dp 紧凑按钮。
4. 原因输入区为 2–3 行浅灰无描边样式。
5. 取消和提交操作右对齐，不使用通栏大按钮。
6. 点击时间依次打开底部日期选择器和底部时间选择器。
7. 日期确认仅更新当前本地表单草稿；时间选择和补卡表单均选择取消。

本轮没有填写原因、没有提交补卡、没有创建审批申请。
