# 审批详情离线快照与打开性能复核

## 结论

- 服务不可达时，审批详情现在优先读取当前账号的 SQLite 快照，不再先等待 20–30 秒网络超时。
- 页面明确显示“当前显示本机审批快照”，并隐藏“更多 / 驳回 / 同意 / 再次发起”等会改变业务状态的入口，避免用户把旧快照当成可操作的在线状态。
- 用户主动点击“重新同步”时才再次请求服务器；网络错误不会清空本地详情或退出登录。
- 通知中心不再等待“标为已读”网络请求完成后才导航；单击通知先进入目标页面，已读状态在后台同步。
- 当前测试服务仍不可达，因此在线状态刷新和真实审批动作没有在本轮执行。

## 问题与修正

修正前，详情加载器使用网络优先策略。服务失联时页面会长时间停留在加载态，随后才回退本地快照；快照页面仍保留审批操作入口，也没有解释数据新鲜度。

本轮改为：

1. `oaApprovalRequestLoaderProvider` 使用 `approvalRequestCacheFirst`，命中账号隔离缓存时直接返回。
2. 详情页监听 OA 同步三态：连接中显示“正在核对最新审批状态”，不可用时显示“当前显示本机审批快照”。
3. 只有同步状态为 `available` 时才渲染业务操作栏。
4. OA 恢复可用后在后台刷新详情；测试环境可关闭自动刷新以稳定验证快照行为。
5. 离线提示使用静态图标，避免无意义的持续动画和测试渲染等待。
