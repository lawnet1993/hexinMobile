# 764 · 移动端附件取消、存储不足与完整性边界复验

日期：2026-09-06，Asia/Shanghai。

结论：**客户端可控边界通过，设备和服务端破坏性边界部分通过。** 预览下载现在可以由用户再次点击进度控件主动取消，离开聊天页也会取消当前预览或历史媒体下载；已完整写入的 4 MiB 分片保留并可在下一次操作中续传。磁盘不足和本地文件异常不再暴露原始路径。普通 IM 附件的 Android 模拟器真实低存储与点击取消已在 [766](766-mobile-attachment-low-storage-cancel-boundary-followup-20260906.md) 补齐；realme 真机、服务端故意返回错误摘要和 iOS 真机仍未执行，因此不能将整个边界写成全部通过。

## 客户端取消与恢复

- `AttachmentPreviewManager` 的确定性测试在第二个分片阻塞时执行取消；取消后仅保留已刷盘的 4,194,304 B `.part`，没有发布正式文件。
- 下一次操作从 4,194,304 B 继续，最终内容逐字节一致，证明取消不会把未完整分片误当成恢复点。
- 聊天页下载音频或视频时，再次点击进度控件会取消；主动取消不显示“播放失败”提示。
- 新预览会话和历史媒体 404 兼容路径都支持取消。历史兼容路径使用 Dio `CancelToken`，取消或失败后删除本次未完成的临时文件。
- 页面关闭时使用 `initState` 缓存的 Manager 引用取消操作，避免在 Riverpod `dispose` 阶段读取 `ref`。该生命周期错误曾被专项测试真实捕获并已修正。

## 存储和摘要完整性

- Android/Linux `ENOSPC`（错误码 28）、Windows 磁盘满（错误码 112）和常见英文错误摘要统一显示“设备存储空间不足，请清理后重试”。
- 其他 `FileSystemException` 统一显示“无法访问本地文件，请检查系统权限或存储空间后重试”，不会把设备绝对路径回显到界面。
- 故意配置错误 SHA-256 的自动化用例通过：摘要不一致时删除临时文件，不原子发布正式文件。
- 本轮没有人为填满真实手机，也没有要求服务端返回被篡改的正文或摘要；后续已在隔离的第三台 Android 模拟器真实触发 `ENOSPC` 并验证提示和清理，见 [766](766-mobile-attachment-low-storage-cancel-boundary-followup-20260906.md)。真机和服务端两项仍保留为未通过，不用模拟器或单元测试替代。
