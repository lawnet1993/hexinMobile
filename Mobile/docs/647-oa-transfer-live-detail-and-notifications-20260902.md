## P1：远端同意后已打开详情不更新，客户端缺陷已修复

复现：M1 发起并转交本人任务给 M2，M1 保持详情页；M2 同意。旧包 M1 仍显示 test02 待处理（10），只读服务端已是 approved（13），且申请人事件流存在同申请通知（14）。

原因：OA 同步刷新了 bootstrap、目录和通知，但详情 Provider 没有监听该申请的更新；缓存优先详情只在打开页面时主动请求一次。收到事件并不等于已打开详情已经更新。

改动：

1. `OaSyncPullResult` 从事件中提取受影响申请 ID，兼容本轮真实的 PascalCase `RequestId` 及 camelCase 字段。通知自身的 `Id` 不作为申请 ID；畸形或无关 payload 不阻塞其他事件。
2. 同步事务成功后才发布按申请 ID 区分的刷新修订号，账号切换时清空；停止的同步循环不再发布完成回调。
3. 当前详情仅监听自己的申请修订号。无关申请变化不会逐个请求已打开详情，不给每个列表项增加网络读取。
4. 保留旧内容直到最新 GET 成功落库；在途刷新合并，期间又有事件则顺序追加一次追平请求，不并发重复拉取。成功后刷新详情投影；失败时保留缓存并禁用不可确认的审批动作。
5. 页面关闭或账号切换后，不再用旧请求结果操作当前页面状态。

复验：最终包第二条申请 M2 同意后，M1 无点击、无下拉就自动展示已同意和意见（20、21）；仍显示整体审批中。此修复不保证服务器未分发给当前账号的事件也能触发刷新。

代码：`collaboration_repositories.dart`、`oa_catalog_sync_coordinator.dart`、`approval_detail_page.dart`。只读核对脚本增加 `-IncludeEvents`，输出仅限本轮标记命中的申请事件元数据，无凭据和原始正文。
