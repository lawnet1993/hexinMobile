# 583 移动端破坏性确认抽屉真机验收

## 结论

移动端残留的三处居中确认弹窗已经统一为从底部展开的紧凑抽屉：退出登录、撤销设备授权、删除所有人的群聊天记录。

- 抽屉使用根导航，覆盖底部主 Tab 与安全区。
- 普通确认使用简短说明和右对齐 40dp 操作按钮。
- 群历史删除使用双重校验：删除原因必填，群名必须完全匹配，确认按钮才可用。
- 键盘弹起时抽屉随输入区上移，标题、风险说明、两个输入区与按钮均保持可见。
- 本轮三处均只打开后取消，没有退出当前账号、撤销任何设备或删除任何群消息。

本轮范围判定：**通过**。

## 改动范围

### 退出登录

旧交互为居中 `AlertDialog`。现在使用紧凑确认抽屉，明确说明退出后需要重新验证终端账号；“退出”保持危险操作颜色。本轮点击“取消”，会话保持登录。

### 撤销设备授权

旧交互为居中 `AlertDialog`。现在使用同一紧凑确认抽屉并显示真实设备名称。本轮对 `Windows device` 只打开确认抽屉后取消，设备授权列表没有变化。

### 删除所有人的群聊天记录

旧交互在居中弹窗内堆叠两个大输入框。现在使用专用底部验证抽屉：

- 明确列出服务器消息、附件、收藏、已读和提及记录都不可恢复。
- 删除原因最多 500 字，使用 2–3 行紧凑输入区。
- 必须输入完整群名 `Mobile-Group-20260825`。
- 原因为空或群名不匹配时，“确认删除”保持禁用。
- 操作按钮高度为 36dp，输入区无强蓝色描边。

真机只打开后取消，没有调用群历史删除接口。

## 保留居中或全屏交互的边界

以下两类没有机械改成底部抽屉：

- 强制客户端更新：属于阻断式系统状态，需要阻止绕过。
- 图片预览：属于沉浸式全屏内容，不是表单或选择弹窗。

除此之外，本轮涉及的个人设置和群管理破坏性确认不再使用 `AlertDialog`。

## 自动化覆盖

新增破坏性验证抽屉测试，验证：

1. 页面不存在 `AlertDialog`。
2. 单行确认输入高度不超过 40dp。
3. 初始确认按钮禁用。
4. 只填写原因或输入错误群名时仍禁用。
5. 原因非空且群名完全匹配后才启用。
6. 返回值保留裁剪后的删除原因与确认群名。
