# 723 IM 提交后立即通知界面，不等待 ACK

## 修正

此前 `pullEvents` 已提交 SQLite，但等待 ACK 请求结束后才由协调器通知界面。如果 ACK 卡住或失败，已落库消息也会延迟显示。

- repository 增加 `onCommitted` 回调，事务成功、会话仍有效且事件确实产生变更时触发。
- coordinator 在回调中按受影响会话通知消息、成员与群详情刷新；保留 generation 防止旧循环发布。
- ACK 仍在事务之后发送，成功才推进确认游标。ACK 成功不再重复发布同一批界面通知。
- 重放和旧会话响应测试保留；不改变同账号消息接收、事务幂等与确认失败处理规则。

## 当前证据

`test/im_ack_visibility_test.dart` 通过真实本机 HTTP 服务和 SQLite 覆盖延迟 ACK 后的 200、500、401、409 四种响应。ACK 未释放时检查消息已落库、applied=1、acked=0、消息变更回调恰好一次；释放后验证确认游标和会话错误处理，没有重复消息或二次发布。500 不触发退出，401/409 仍交会话失效处理。

2026-09-05 当前全量 1279/1279、静态分析无问题；含此改动普通 Profile 包已保留数据安装真机，安装与数据保留证据见 725。

## 边界

本机测试不是线上 ACK 故障注入。没有据此认定新版 Push Gateway 已接入，也不能解释或修复 720 中桌面数据库缺少消息的问题。完整跨桌面同步验收仍未通过。
