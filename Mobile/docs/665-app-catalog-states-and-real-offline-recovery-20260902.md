## 修复内容

`AllAppsPage` 原先把 FutureProvider 的加载中、异常和真正空目录都折成空列表，统一显示“暂无匹配应用”；首页失败时可能只显示“更多”。

新增共享 `ApplicationCatalogContent`，用于首页和全部应用：

| 情况 | 展示与行为 |
| --- | --- |
| 首次加载，无当前账号缓存 | 小加载指示与“应用加载中” |
| 加载失败，无缓存 | “应用加载失败”、安全错误摘要、重试 |
| 后台确实返回空目录 | “暂无可用应用”，不伪造“更多”或本地应用 |
| 有应用但搜索不匹配 | “暂无匹配应用” |
| 服务不可达且有缓存 | “连接暂不可用，显示缓存应用”，原目录和搜索保留 |
| 后台更新失败，有本账号缓存 | 保留应用并显示更新失败提示 |
| 手动重试 | 调用真正网络刷新，禁止重复点击；成功后重新读取缓存，不只是 invalidate 一个 cache-first 读取 |
| 服务恢复 | 对暂时性错误每次恢复最多自动重试一次；记住恢复发生在请求仍未完成期间的情况 |
| 权限、认证等永久失败 | 不因联网而无限自动重试，保留明确错误 |
| 切换账号、页面关闭 | 丢弃旧账号缓存/迟到操作结果，不刷新新账号的目录 |

只接受当前账号已成功完成的目录数据，避免 Riverpod 在依赖重新加载、甚至随后失败时仍保留前一账号 AsyncValue 的值。仓库网络刷新沿用已有会话绑定及 SQLite 提交检查。演示模式不会通过新增重试入口请求真实仓库。

实际截图发现第一版状态条仍偏高（60dp），本轮进一步压到最小44dp；重试中保持44dp，避免仅因加载图标替换按钮而让目录跳动。较大文本仍可自然增高，未固定裁切。
