# 843 · 移动端弹窗与底部抽屉交互边界审计

时间：2026-09-09（Asia/Shanghai）

## 结论

当前移动端 OA 不再使用桌面式居中表单弹窗：

- 单选、多选：底部选择抽屉。
- 日期、时间、日期范围：底部选择抽屉。
- 待办筛选、新建事项：可滚动底部抽屉。
- 同意、驳回、撤回、转交、前后加签、退回、催办：底部操作或文本输入抽屉。
- 审批流程：直接在详情页面内展开，不额外弹窗。

全项目剩余居中/全屏 Dialog 仅用于以下明确场景：

- 强制更新：不可绕过的居中阻断弹窗。
- 头像库：有限选项的视觉网格，居中展示比长抽屉更合适；自定义头像继续进入系统选择与裁剪。
- 聊天图片预览：沉浸式全屏图片查看，不属于表单选择弹窗。

聊天表情、@成员、消息操作、群管理、联系人备注及其他轻量选择继续使用底部抽屉，符合移动端单手操作路径。

## 验证

- 对 `Mobile/lib` 全量检索 `showDialog`、`AlertDialog`、`SimpleDialog` 和 `Dialog`，没有发现 OA 页面残留 Dialog。
- OA 请求页字段交互均调用移动端 Choice、MultiChoice、Date、Time、DateRange 抽屉。
- OA 详情动作均调用移动端 TextInput、Choice、Confirm 或成员选择抽屉。
- 当前全量 Flutter 回归 1424/1424 通过。

## 边界

- 这是当前代码和组件回归证据；后台新增未知字段类型时仍需确认其渲染器落入已有移动端抽屉，而不是自行引入 Dialog。
- 强制更新与图片全屏预览保留 Dialog 是有意设计，不应机械改成底部抽屉。
