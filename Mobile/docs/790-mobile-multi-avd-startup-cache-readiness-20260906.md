# 移动端多虚拟机启动与缓存可用性复验（2026-09-06）

## 结论

本轮在 3 台保持独立账号、安装身份和本地数据库的 Android 虚拟机上完成并行冷启动，又在硬件加速设备上完成 3 次受控冷启动。结果为：

- 缓存工作台在网络同步完成前可用，启动链路没有等待 IM/OA 网络响应才展示业务数据。
- 单台硬件加速虚拟机的 Activity 冷启动为 1.758–2.285 秒，Dart 启动后的缓存工作台可用为 1.244–1.516 秒。
- 3 台同时冷启动的 Activity 时间为 3.772–7.379 秒；最慢设备使用 SwiftShader 软件渲染，另两台使用宿主机 NVIDIA OpenGL。该组数据是多实例压力上界，不作为真机日常性能结论。
- 并行启动没有造成登录丢失、账号串用或本地缓存清空。

## 本轮改造

Profile 模式新增一次性、纯数字的启动阶段：

1. `secureSessionHydrated`：系统安全存储中的会话读取完成；
2. `shellCreated`：五个主 Tab 的 Shell 已创建；
3. `shellFirstFrame`：Shell 第一帧完成；
4. `workbenchCacheReady`：账号隔离的 OA 本地缓存已解密并可渲染；
5. `collaborationSyncRequested`：后台 IM/OA/在线状态同步开始请求。

每个阶段每个进程最多记录一次，不包含账号、Token、消息、URL、设备身份或业务数据；Release 和 Debug 模式不安装该诊断。采集脚本支持选择 4 个固定测试虚拟机，仍拒绝任意设备参数和 evidence 目录之外的输出位置。

## 三机并行冷启动

| 设备 | 渲染器 | Activity 冷启动 | Shell 首帧（Dart 后） | 会话恢复（Dart 后） | 工作台缓存可用（Dart 后） |
| --- | --- | ---: | ---: | ---: | ---: |
| M1 | NVIDIA host GPU | 6.654 秒 | 1.522 秒 | 3.057 秒 | 5.043 秒 |
| M2 | SwiftShader | 7.379 秒 | 1.574 秒 | 3.152 秒 | 5.345 秒 |
| M3 | NVIDIA host GPU | 3.772 秒 | 0.187 秒 | 0.957 秒 | 1.858 秒 |

并行采样时，Shell 首帧之后立即发起同步请求；安全存储和本地缓存恢复均继续异步完成。M2 首帧 raster 最大约 407 ms，并且系统确认其使用 SwiftShader，因此它适合用于低性能边界，不适合作为正常真机基线。

## 单机受控冷启动

停止另外两个 App 进程后，在 M3 连续执行 3 次 `force-stop → cold start`：

| 样本 | Activity 总时间 | Shell 首帧（Dart 后） | 会话恢复（Dart 后） | 工作台缓存可用（Dart 后） |
| --- | ---: | ---: | ---: | ---: |
| 1 | 2.285 秒 | 0.033 秒 | 0.920 秒 | 1.308 秒 |
| 2 | 1.758 秒 | 0.026 秒 | 0.865 秒 | 1.244 秒 |
| 3 | 2.009 秒 | 0.029 秒 | 1.008 秒 | 1.516 秒 |

三次均保留原登录和账号缓存。结果也说明 `am start -W` 只能代表 Android Activity 总时间，不能代替 Flutter 业务页面可用时间；后续性能回归应同时使用本轮分段指标。

## 资源与压力解释

- 三台进程本轮稳定 PSS 约 177.4、184.6、178.3 MiB。
- 采样时宿主机可用内存约 4.42 GiB。
- 多实例并行会竞争 Flutter Engine 初始化、GPU/vsync 和宿主 CPU；并发数据用于发现退化趋势，不能直接外推到物理设备。
- 真机本轮处于锁屏休眠，未把它计入首屏性能通过证据。需用户解锁并保持屏幕点亮后再补同一版本的真机 Profile 样本。
