# 600 通知列表连续滚动与分页恢复

## 当前结论

移动端通知中心已移除“加载更多”按钮，改为符合移动端习惯的连续滚动分页。用户接近列表底部时自动读取下一页；第一页内容不足一屏且服务端仍返回 `hasMore` 时自动补页。分页失败不会清空已经显示的通知，也不会立即无限重试；下一次真实上滑会清除该游标的错误缓存并重新请求。

## 实现边界

- 首次页和下一页继续使用桌面同源 `/api/oa/notifications/page` 及 `cursor / unreadOnly` 契约。
- 距离列表底部 240dp 时触发下一页，`_loadingMore` 阻止并发重复请求。
- 下一页按通知精确 ID 合并，不覆盖第一页或已显示的 IM 投影。
- 首屏不足一屏时按游标顺序补齐，直到填满视口或服务端返回 `hasMore=false`。
- 临时失败只失效当前游标 Provider；现有列表保留，新的上滑手势才允许重试，避免错误状态自循环。
- 切换“全部 / 未读”会清理分页状态并回到列表顶部，不混用两个筛选的游标。
