# 853 · OA 提交强杀恢复与加密临时文件清理

时间：2026-09-09（Asia/Shanghai）  
范围：Flutter Mobile / OA 草稿附件、IM/OA 加密文件容器

## 真实复现

- emulator-5556 使用测试服 Test Terminal 03 打开“请款审批”，填写金额、类型、日期和 `AI-UAT-OA-UPLOAD-CRASH-20260909` 说明。
- 选择 19 MiB 文本附件，页面显示 `1 / 20`、附件 `19.0 MB`，应用私有目录只保存加密容器。
- 点击“提交申请”后 350 ms 强制停止进程，PID 从 3430 变为重启后的 6486。
- 重启进入草稿箱后，`AI-UAT` 请款草稿、全部表单值及 19 MiB 附件均恢复；没有产生重复申请，也没有提交正式业务数据。
- 删除附件和该测试草稿后，原有请假草稿仍保留。

这次强杀发生在提交准备阶段；证据不足以证明已经进入服务端 multipart 传输，因此“真正上传中杀进程”仍保留为未完全通过。

## 发现与修复

强杀在加密分片写入与原子重命名之间留下一个 1,835,152 bytes 的 `.imq.tmp`。该文件没有数据库引用，删除草稿后仍会占用空间。

共用加密文件仓储现在在新进程首次访问当前账号时执行一次尽力清理：

- 只清理当前账号目录中的 `.imq.tmp`；
- 不删除完整 `.imq`、其他后缀或其他账号文件；
- 目录不可用或平台插件尚未注册时不阻断登录、同步或业务操作，下次启动继续尝试；
- IM Outbox 与 OA 草稿共用同一安全边界。

- 保留真实 1,835,152 bytes 残留，覆盖安装新构建并启动；启动前残留存在，启动后目录文件数为 0，应用 PID 7443 正常存活。
- 新增账号隔离测试：当前账号残留被删除，完整文件、普通临时文件和其他账号残留均保留。
